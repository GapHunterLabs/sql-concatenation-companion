Reports a SQL statement built by string concatenation or interpolation with a value that could carry injected SQL, when the result is passed to a call that runs SQL (executeQuery, rawQuery, createNativeQuery, cursor.execute, ...). Java, Kotlin and Python files.

Example:

stmt.executeQuery("SELECT * FROM users WHERE name = '" + name + "'");
cursor.execute(f"SELECT * FROM users WHERE id = {user_id}")

Not reported: literals, constants (TABLE_USERS), numbers (an int parameter, %d placeholders), locals last assigned a literal, and commented-out code.

The quick-fix replaces the interpolated value with a ? placeholder where it sits inside the string and adds a TODO(sql-concat) comment naming the value to bind as a real parameter.
